| 引擎 | 核心算法 |
|---|---|
| `mood` | 连续数值 + 10 档位 + 线性衰减（0.01/分）+ 双向地板 ±0.5 + 加权（旧0.5+新0.5） |

# 板块 H：你提的疑点核查

## H.1 `plan.judge_outcome()` 词表缺口 —— **真问题，但影响有限**

**实测【实测】：**

| 输入 | 判定 | 期望 |
|---|---|---|
| 我做完了 | `unknown` | success |
| 做完了 | `unknown` | success |
| 完工了 | `unknown` | success |
| 升级好了 | `unknown` | success |
| 已经更新了 | `unknown` | success |
| 弄完了 | `unknown` | success |
| 干完了 | `unknown` | success |
| 上线了 | `unknown` | success |
| 装上了 | `unknown` | success |
| 搞定了 | `success` | ✅ |
| 做好了 | `success` | ✅ |

**现有 `SUCCESS_WORDS`（20 个）：**
```python
('升级了','升好了','弄好了','搞定了','做好了','装好了','改好了',
 '已经给你','已经加','加了','给你了','看吧','你看','应该好了',
 '可以了','成了','办好了','买好了','发了','给你弄')
```

**影响评估：**

| 维度 | 判断 |
|---|---|
| **会不会误删计划** | ❌ **不会**。`unknown` → `should_close()` 返回 False → 计划留着 |
| **会不会漏判成功** | ✅ **会**。你说"做完了"，系统听着像没人回应 |
| **后果** | 计划一直挂着，10 天后又触发一次 → 她再问一遍「升级呢」 |
| **严重度** | 🟡 **中**。不致命，但会让计划积压 + 她显得"记不住" |

**根因不止是词表小**：`judge_outcome(text)` 只看文本，**不知道计划内容是什么**。所以：
- 「做完了」——指升级？还是指作业？
- 「还没说完」——命中 `还没`（失败词）→ 误判 failure

**修法建议（按性价比）：**

| 方案 | 改动 | 效果 |
|---|---|---|
| **A. 补词表** | 加「做完了/完工了/更新了/弄完了/干完了」等 | 立刻改善，但治标 |
| **B. 给函数加计划内容参数** | `judge_outcome(text, plan_evidence)`，做语义关联 | 治本，但要改签名 |
| **C. 直接交给模型判** | 在巩固时让模型看「计划 + 他说的话」一起判 | 最准，复用已有机制（主人定的 A1 就是这个方向） |

**我倾向 C**——因为主人已经定了「有啥要判断的扔流水账里，跟系统层说一嘴就一起判断了」。

# 板块 L：结论

**这个项目的架构是清晰的、分层是合理的、测试是扎实的（1088 条）。**

**但有三个系统性风险：**

1. **四个新引擎里三个从未被真实数据跑过**（mood / cognition / forgetting 实际 0 产出）—— 这是最大的未知
2. **遗忘的中间档断头**（`review_candidates` 零调用）—— 设计好的一环没接上
3. **3.4 天没有输入** —— 所有新改动都缺真实场景验证

**如果要我给一个优先顺序：**

| 优先级 | 动作 |
|---|---|
| **1** | 让系统跑起来（真实对话进去），观察 mood / cognition 有没有落盘 |
| **2** | 接上 `review_candidates`（遗忘中间档） |
| **3** | 补 `judge_outcome` 词表（或改成让模型判） |
| **4** | 清理 4 个死函数 + 1 个死配置 |
