> 核实时点：2026-11-09 17:0x
> 标准：**一个前台 + 一个后台 = 一个最小单位。只有一个，就是残缺。**
> 方法：逐个配对验证「去程」和「回程」是否都通——**有函数 ≠ 配对通了**

---

## 零、核心判断

**小鱼的循环是开的，不是闭的。**

九项能力像个九个零件，但**零件之间的回程大面积缺失**。具体分成三类：

| 状态 | 数量 | 后果 |
|---|---|---|
| ✅ **成对（前后台都通）** | 2 对 | 能自己转 |
| ⚠️ **半对（有去程无回程）** | 3 对 | 后台产出用一次就消失 |
| ❌ **单边（只有前台或只有后台）** | 2 对 | 根本没形成单元 |

# 三、按你的标准，缺的是什么

**你说「一个前台 + 一个后台才算最小单位，只有一个就是残缺」。**

**按这个标准，小鱼现在只有 1 个完整单元（心情），1 个近似完整（巩固→召回），其余 5 个都残缺。**

**而这些残缺有一个共同的形状：**

```
后台产出了 → 送到前台 → 前台用一次 → 消失
                ↓
         没有回到后台
```

**这正是「碎片化智慧」的技术定义：每一次产出都是一次性的，不进循环。**

# 四、补法（按「成对」标准）

## 缺回程 1：想法要能回到后台

**现在**：`delivered` = 死。

**要补的回程**：

```
想法被消费后，记一条结果：
  · 她说了（说了什么）→ 这句话进流水账 → 下次巩固能抽到
  · 她没说（为什么）→ 至少记一笔"这条没被用上"
```

**最小实现**：`consume_inner_os` 消费时，同时写一行 `system_log`：
```
[系统] 想法上浮：{想法内容} {用了/没用}
```

**这样巩固时模型就能看到「哪些想法真被用上了」，而不是每次从零想。**

## 缺回程 2：人格要能接受后台的更新

**现在**：人格复盘只提建议，建议 7 天过期。

**要补的**：

```
人格复盘的产出 → 不是推到 inner_os → 而是：
  ① 记一条 system_log：「人格建议：{内容}」
  ② 巩固时，模型看到「最近的自我叙事 + 人格建议」→ 决定要不要改人格
  ③ 改了就写 persona.md（留 .bak）
```

**这样「自我建模」才成对：前台读人格，后台改人格。**

## 缺回程 3：遗忘要真的动

**现在**：`deleted` 恒为 0。

**问题不在阈值，在于**：
- 记忆太少（7 条），没有够旧够不重要的
- 或者回程（review 档）没触发

**实测**：`review=0` 说明中间档也没候选。

**先不急着改阈值**——等记忆积累到几十条再看。**但要知道这是空的。**

## 缺回执 4：认知要能被验证

**现在**：7 条认知，没有一条记录过「准不准」。

**要补的**：

```
「他讨厌人群」这条认知
   → 后来每次被召回、被用上 → 记一次 use_count
   → 如果后来发现相反证据（他说他其实喜欢热闹）→ 记一次 contradicted
```

**这对应你 11-06 定的 add/replace/merge/conflict 四种 action——那个设计已经在，只是没跑过。**

# 五、一句话

**按「前台 + 后台才算完整」这个标准，小鱼现在只有心情这一对是真的活的。**

**其余的都是「后台产出 → 前台用一次 → 消失」，形不成循环。**

**补法不是加新功能，是给每一对补上回程。**

**而现在唯一有真实数据能验证的，是「计划」那一对——再等 3.4 天，第一批计划临期，就知道回程做对了没有。**
