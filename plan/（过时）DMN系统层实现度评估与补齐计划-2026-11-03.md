## 四、三个结构性缺口（都实测过）

### 🔴 A. `_read_recent_chat` 写死只读 `pet`，主动说话拿的是 10-30 的对话

`system.py:_read_recent_chat()` → `channel = 'pet'`。而 pet 最后一条是 **10-30 12:16**，
真实对话在 `qq_private`（最后 11-03 01:21）。

后果：今天三次主动说话（01:09 / 01:54 / 13:22），`signals.recent_chat` 里全是**四天前**的内容：

```
id=892  10-30 12:16  怎么啦，是遇到什么事了还是单纯有点闷
id=891  10-30 12:16  主人: 今天心情不太好
id=828  10-30 00:21  主人: [图片]
```

**这是 13:22 那句「刚刚说心情不好现在好一点了吗」的真实来源——"刚刚"其实是 10-30。**

这与上一轮修掉的「人格复盘只读 pet」「安慰三态只读 pet」是**同一个根**，只是第三处漏网。

### 🔴 B. `emotion` 只写不读（半残器官）

`system_state.emotion` 每次主动说话都写，但读它的**只有 `role_speak.py:108`**。
`build_messages()` 里一个字都没有（已 grep 确认）。

后果：她主动说话时"知道"自己心情 confused；你回一句，她**立刻失忆**——
被动回复完全不受心境影响。这不是心境演化，是单向写入。

### 🟠 C. 巩固的成功是靠**历史积压**撑的，不是增量

3 次成功分别处理 184 / 191 / 134 条，全是积压。`consolidate_min_new_turns = 8`，
日常聊天根本攒不满 → 每小时基本都在报 `not_enough_new`。

这不算 bug（省钱是正确设计），但意味着**日常使用中巩固的实际频率远低于设计意图**——
"她越聊越懂你"这件事，在真实节奏下发生得比设计的慢得多。

### 🟡 D. 牵挂闭环缺最后一步验证

`deferred_care`（事件 13，`due_ts` = 11-04 01:50）→ `schedules` 有 1 条 → 心跳到点会捞起
→ 转 `inner_os` → 角色层带 `_recheck_context` 重判。**路径全通、测试全过，但生产上一次没 fire 过。**

它同时踩到两个设计点（带当前状态重判、群渠道不排班），值得盯着。

## 五、补齐计划（**16:10 重排优先级**）

> **重排理由**：主人明确说「忙着计划开发，没时间聊天」。
> 实测数据支持这个使用模式：**26 段真实会话，中位数 4 条消息，61% 低于门槛 8**。
> 所以"让低频使用也能正常工作"必须排在最前面，而不是按原计划的性价比排序。

### 🔴 P0｜巩固门槛：让低频使用也能记住（**新增最高优先级**）

**这是当下最痛的一条**，因为它直接导致"你聊了，但她没记住"。

实测问题：

```
consolidate 38 次，成功 3 次 = 7%
真实会话中位数 4 条，61% 低于门槛 8
pet 渠道攒了 5 条，从 10-30 卡到现在（4 天，永远凑不够 8）
```

**更麻烦的是攒着的那段没有保护**：两次相隔几天的聊天会被凑成一批巩固，
抽出来的事实**串在一起**（三天前的 A 事 + 今天的 B 事）。

- [ ] `system.py`：`_consolidate_channel()` 加"最长等待"旁路
      ```python
      # 距上次成功巩固超过 N 小时，且有 >= 2 条增量 → 不等门槛，直接跑
      idle_hours = (time.time() - float(st.get("last_consolidate_ts") or 0)) / 3600
      max_wait = float(SYSTEM.get("consolidate_max_wait_hours", 12))
      if len(turns) >= 2 and idle_hours > max_wait:
          pass  # 跳过 min_new 门槛
      ```
- [ ] `config.json`：补 `system.consolidate_max_wait_hours = 12`
- [ ] 单测：只攒 3 条、但距上次巩固 13 小时 → 应该跑；只攒 3 条、1 小时前刚跑过 → 不跑
- [ ] ⚠ **别直接降门槛到 4**：那会让每条消息都调一次模型，成本失控

**验收**：连续两天、每天只聊 3 句，`consolidate` 成功率从 7% 升到 >50%。

### 🔴 P0｜修 A：把 `recent_chat` 改成跨主渠道（半天）

- [ ] `system.py`：新增 `_read_recent_chat_multi()`，按 **pet + 主人私聊** 合并取最近 N 条
      （私聊仍过 `_filter_owner_turns`，陌生人/系统注入照旧被挡；群聊不进）
- [ ] `_tick_body()` 的 `signals["recent_chat"]` 换用它
- [ ] 补 `signals["recent_chat_age_minutes"]`——让角色层**知道素材有多旧**，
      避免再把四天前的对话说成"刚刚"
- [ ] 单测：pet 无新对话、私聊有新对话时，signals 里能拿到私聊那几条

**验收**：下一次主动说话，`recent_chat` 的内容时间与当前相差 < 1 天。

> 这条和 `7d4dfdc`（人格复盘/安慰三态）是同一根（pet 假设失效），只是当时没查到这一处。
> **三处同源问题应该一次修完，别留第四处。**

### 🟠 P0｜修 B：让心境回流到被动对话（半天）

- [ ] `build_messages()` 注入一段"你现在的心境"：`system_state.emotion` + `focus` + 最近一次
      主动说话的时间（如果 2 小时内说过，她应该记得自己刚开过口）
- [ ] 措辞要短，别写成状态报告；只给主人私密空间注入（群聊不注入 —— 心境是私人的）
- [ ] 单测：有 emotion 时 system 块出现；群聊时不出现

**验收**：主动说完话后立刻对话，她的回复能体现出"刚说过什么"的连续性。

**为什么值得做**：这是唯一"机制已建、数据已产、就差一处读取"的项，改动最小、语义收益最大。

### 🟠 P1｜新增：给自建记忆库补"遗忘"（**插件停用后新增的工作**）

## 七、风险与边界

| 风险 | 对策 |
