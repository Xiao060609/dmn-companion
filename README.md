# 小鱼 · 一个有默认模式网络的陪伴型对话系统

> 这篇 README 回答三件事：**这是什么**、**为什么长这样**、**怎么跑起来**。

---

## 这是什么

一个**跑在本机的 AI 陪伴角色**。不是助手，是"住在这台电脑里的人"。

它和一般 chatbot 最根本的区别在**记忆和节律**：

* 她**会忘**。记忆按类型老化——计划两天、琐事七天、喜好两个月、事实半年。
* 她**会自己醒来**。后台每五分钟检查一次有没有值得在意的变化，没有就不打扰你。
* 她**主动找你**之前会先问自己：这件事值得说吗？现在说合适吗？
* 她说出口的每句话只来自**一个嗓音**。后台系统不产生任何台词，只负责判断和刹车。

### 和别的陪伴项目的差别

大多数"AI 女友/桌宠"项目是**提示词工程**：写一段人设，接一个模型，完事。
这个项目把**认知机制**当工程问题做：

| 问题 | 这里的做法 |
|---|---|
| 记忆无限增长怎么办 | 指数衰减 + 按类型给不同半衰期 + 用得越多越稳固 |
| 同一件事记了十遍怎么办 | 写入前向量检索旧记忆，让模型判断该合成、替换还是并存 |
| 她老说"我什么都不记得" | 三层记忆：对话日志 / 状态机事件 / 长期事实库 |
| 角色扮演着就串戏 | 被动请求和主动心跳**彻底分线**，互不干扰 |
| 主动说话很烦人 | 决策权在角色层，系统层只守额度与冷却 |

## 为什么叫"默认模式网络"

DMN（Default Mode Network）是神经科学里的一个真实结构：人在**不专注外部任务时**
大脑活跃的那组区域，负责回忆过去、想象未来、揣测他人、构建自我叙事。

这个项目把它当**架构蓝本**，不是修辞：

| DMN 的功能 | 这里的实现 |
|---|---|
| 静息态（无任务也在运行） | 心跳线程，每 5 分钟一次，纯代码零模型调用 |
| 回忆过去（反刍） | `ruminate` —— 夜间梳理，重读当天对话 |
| 想象未来（预演） | `prospect` —— 推演接下来可能发生什么 |
| 揣测他人（心智理论） | `theory_of_mind` —— 更新对这个人的理解 |
| 自我叙事 | `self_narrative` —— 我是谁 |
| 突显网络（什么值得注意） | `_detect_change()` —— 变化检测，没有变化就不惊动模型 |

**这是借鉴概念，不是模仿实现。** 上面每一个都落到了具体代码，也各自有取舍和妥协，
文档里写清了哪些是"抄的"、哪些是"自己想出来的"。

## 三个核心设计

### 1. 两层分离，台词只有一个出口

```
        被动 · 实时                     主动 · 旁路
   用户说话 → 角色层              心跳 → 系统层
              ↓                          ↓ 只报信号
         她自己决定                   她自己决定说不说
              ↓                          ↓
         唯一的台词出口 ◄────────────────┘
```

**系统层不产生任何文本。** 它只做三件事：检测变化、判断额度、记录流水账。
说不说、说什么，永远由角色层决定。

这条规则来自一次失败：早期版本让系统层也用模型说话，结果是
**延迟翻倍，出了错分不清是哪一层**。

### 2. 记忆是会老的

不是"存下来就一直记得"，而是**按性质给不同寿命**：

| 类型 | 初始 TTL | 衰减曲线 | 例子 |
|---|---|---|---|
| `EPISODIC` | 7 天 | 指数 | 今天加班到十点 |
| `PLANNED` | 2 天 | 阶梯 | 明天要交作业 |
| `FACTUAL` | 180 天 | 指数 | 他住在重庆 |
| `RELATIONAL` | 90 天 | 线性 | 他有个室友叫老王 |
| `PREFERENCE` | 60 天 | 指数 | 他喜欢灰色 |

再叠加两个因子：**重要度**（0.5~1.5 倍）和**被回忆次数**（越用越稳固，1.0~1.5 倍）。

衰减用半衰期形式 `2^(-t/(TTL/2))`，不是 `e^(-t/TTL)`——后者在到期时还剩 37%，
看起来还很新，不符合"该忘了"的直觉。

### 3. 写入前先问一遍"我是不是已经知道了"

新增一条事实时，先在向量库里检索相关旧记忆，交给模型判断：

* 同一件事换个说法 → 合成一条
* 新事实取代旧的 → 用新的
* **两条矛盾** → 合成一条，把矛盾写进同一句（「他说讨厌人群，但天天泡在群里」）
* 完全无关 → 旧的保持不动

三条安全铁律：**先插新的、成功后再删旧的**（否则 embedding 一失败两条都没了）；
解析失败按纯新增处理（宁可重复，不可误删）；只和同一会话的记忆合并。

## 怎么跑起来

### 最小跑法（只要网关，不要桌宠和 QQ）

```bash
cd gateway
pip install -r requirements.txt
python gateway.py
```

打开 <http://127.0.0.1:8898/health>，看到 `{"ok": true}` 就算起来了。

**还需要一个模型**。默认配置指向本地 LM Studio（`127.0.0.1:1234`）；
用云端的话改 `gateway/config.json`：

```jsonc
"endpoint": {
  "base": "https://dashscope.aliyuncs.com/compatible-mode/v1",
  "model": "deepseek-v4.1-flash-1017",
  "timeout_s": 120
}
```

然后把 key 写进 `gateway/secrets.json`（**这个文件在 .gitignore 里，不会被提交**）：

```json
{ "dashscope_api_key": "sk-..." }
```

### 完整跑法（桌宠 + 语音 + QQ）

需要额外自己装这些第三方项目：

| 组件 | 作用 | 我们怎么用它 |
|---|---|---|
| [AstrBot](https://github.com/AstrBotDevs/AstrBot) | QQ 机器人框架 | HTTP 调用 + 定制插件 |
| [Breeze-TTS-2.cpp](https://github.com/HoppouAI/Breeze-TTS-2.cpp) | 本地语音合成 | 子进程 + HTTP |
| [SnowLuma](https://github.com/) | QQ 协议端 | 进程外调用 |
| Live2D Cubism | 形象渲染 | 需自备模型素材 |

> ⚠ **本仓库不含**：Live2D 模型素材（第三方版权）、
> Breeze-TTS 引擎与模型权重（3.5 GB）、AstrBot / SnowLuma 源码。
> `qq/` 下只有本项目的定制部分。
>
> **各组件许可证不同，务必先看 [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md)。**
> 其中两条值得先知道：**AstrBot 是 AGPL-3.0**（改它本体就要开源改动）；
> **Breeze 的模型权重是非商业许可**（商业用途需自行确认授权）。

### 跑测试

```bash
python -m pytest gateway/tests -q     # 1097 passed, 2 skipped
python -m pytest desktop/tests -q     # 135 passed
```

## 诚实的边界

这个项目**不是**通用的陪伴产品，它为一台机器、一个人写成。开源时保留了机制，
去掉了具体的人和事。你知道这些会更好上手：

* **人格是提示词，不是训练出来的**。换 `persona.md` 就是另一个人。
* **记忆质量取决于模型**。用弱模型时，抽取和合并都会变差。
* **情感是真的还是演的？** 这个项目没有回答，也不打算回答。它只保证
  **行为一致**：她记得你说过的事，她忘得符合规律，她主动开口前会先想。
* **大部分测试是单元测试**。真实对话质量需要长期使用才看得出来。
